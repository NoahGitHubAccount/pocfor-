## 1. 系統目的

接收市民陳情文字，自動預測應分派的局處，回傳 Top-N 候選結果與信心值。原人工初分流程由 AI 輔助，最終決定仍由人工確認。

## 3. smart-ai 架構

### 3.1 核心概念

| 層級 | 說明 | 範例 |
|------|------|------|
| **system** | 一個業務系統（對應一個客戶） | `taitung_bigdata`、`chiefmail_back` |
| **org** | system 底下的機關（各自獨立模型與標籤） | `hpa`（警察局）、`edu`（教育局） |

- `taitung_bigdata`：無子機關，system 共用一個模型
- `chiefmail_back`：多個 org，各 org 獨立訓練、獨立 checkpoint

### 3.2 部署拓樸

| 環境 | 說明 |
|------|------|
| **dev** | 多 system 並存同一容器，方便驗證所有 system |
| **prod** | 每個客戶機器只跑**一個** system，其他 system 不存在於容器內 |

prod 環境不需 LRU 快取，model_manager 維持單一 lazy cache，API Key 足夠作為內網認證。

### 3.3 目錄結構

```
smart-ai/
├── api/
│   ├── main.py                     # FastAPI create_app()，lifespan 管理 ModelManager
│   ├── middleware/auth.py           # X-API-Key 驗證（缺少 key → 401，非 422）
│   └── routers/
│       ├── predict.py              # POST /api/v1/predict
│       ├── batch.py                # POST /api/v1/batch
│       └── train.py                # POST /api/v1/train（202 非同步）
│
├── core/
│   ├── model_manager.py            # Lazy import（首次 request 才載入 torch）
│   ├── db_connector.py             # DBConnector ABC；MySQLConnector 實作，MSSQL stub
│   └── scheduler.py                # APScheduler（備妥未接線，Phase C 啟用時接回）
│
├── src/
│   ├── config.py                   # YAML loader（先讀 system，再疊加 org）
│   ├── train.py                    # 訓練邏輯，支援外部傳入 cfg
│   └── predict.py                  # Predictor class
│
├── systems/
│   ├── taitung_bigdata/
│   │   ├── config.yaml
│   │   └── checkpoints/current -> vYYYYMMDD/
│   └── chiefmail_back/
│       ├── config.yaml             # system 共用設定
│       └── orgs/
│           ├── hpa/config.yaml     # org 設定（覆蓋 system 設定）
│           └── edu/config.yaml
│
├── tests/test_api.py               # L1 smoke tests（不需 torch，8/8 pass）
├── Dockerfile                      # prod（含 torch CPU）
├── Dockerfile.test                 # L1 測試（不含 torch）
└── docker-compose.yml
```

### 3.4 設定檔階層

設定採 system 層 + org 層疊加，org 層優先：

```yaml
# systems/chiefmail_back/config.yaml（system 層）
input_fields: [subject, content]
pretrained_model: hfl/chinese-roberta-wwm-ext
max_length: 512
epochs: 5
```

```yaml
# systems/chiefmail_back/orgs/hpa/config.yaml（org 層）
org: hpa
num_classes: 12
train_file: data/train.txt
labels_path: data/labels.txt
model_dir: checkpoints/bert
db:
  field_map: {label: unit, text: subject}
```

### 3.5 模型版本管理

訓練完成後自動建立版本目錄，`current` 軟連結永遠指向最新版：

```
checkpoints/
├── current -> v20260517/   # model_manager 自動 follow 此軟連結
├── v20260517/              # 最新 checkpoint
└── v20260430/              # 舊版（可手動清理）
```

## 4. 部署

### 4.1 環境需求

| 項目 | 需求 |
|------|------|
| 作業系統 | Linux / WSL2（Rocky 9 或 Ubuntu） |
| Docker | 29.x 以上 |
| Docker Compose | v2 以上 |
| GPU（推論） | 非必要，CPU 可跑 |
| GPU（訓練） | 建議 NVIDIA 8GB+ VRAM |

### 4.2 環境變數

| 變數 | 必填 | 說明 |
|------|------|------|
| `SMART_AI_API_KEY` | ✅ | API 認證金鑰 |
| `SMART_AI_SYSTEMS_ROOT` | 否 | systems/ 根目錄（預設相對 api/ 的 `../systems`） |
| `DB_HOST` / `DB_USER` / `DB_PASSWORD` / `DB_DATABASE` | 訓練時必填 | MySQL 連線（密碼不從 API request 傳入） |

### 4.3 dev 啟動

```bash
cd smart-ai
docker compose up -d api
curl http://localhost:8080/health
# 預期：{"status": "ok"}
```

### 4.4 prod 啟動（單一 system）

```bash
docker run -d -p 8080:8080 \
  -e SMART_AI_API_KEY=<key> \
  -e DB_HOST=<host> -e DB_USER=<user> \
  -e DB_PASSWORD=<pw> -e DB_DATABASE=<db> \
  -v /data/chiefmail_back:/app/systems/chiefmail_back:ro \
  smart-ai:latest
```

### 4.5 L1 Smoke Test（不需 GPU）

```bash
docker compose build test
docker compose run --rm test
# 預期：8/8 passed
```

### 4.6 新模型上線

`/api/v1/train` 完成後 `current` 軟連結自動更新；API 下次 request 時 lazy 載入新版本。需立即重新載入：

```bash
docker compose restart api
```

### 4.7 常見問題

| 症狀 | 原因 | 處理方式 |
|------|------|---------|
| 404 | config.yaml 找不到 | 確認 `systems/<system>/[orgs/<org>/]config.yaml` 存在 |
| 503 | `current` 軟連結不存在或 checkpoint 空目錄 | 先執行 `/api/v1/train` 或手動放入 checkpoint |
| 500 | 未設定 `SMART_AI_API_KEY` | 補設環境變數 |
| 訓練 500 | DB 連線失敗 | 確認 `DB_*` 環境變數已設定 |

## 5. 模型評估

### 5.1 指標說明

**Macro F1** 為主要評估指標（Accuracy 對類別不均衡有誤導性）：

> 本資料集警察局佔 31%。若模型全猜警察局，Accuracy 達 31%，但 Macro F1 近 0。

### 5.2 BERT POC 基線（2026-04-20，臺東縣政府資料）

| 局處 | BERT F1 | 說明 |
|------|---------|------|
| 社會處 | 0.86 | 穩定 |
| 警察局 | 0.84 | 穩定 |
| 教育處 | 0.79 | 穩定 |
| 交通及觀光發展處 | 0.77 | 穩定 |
| 環境保護局 | 0.73 | 穩定 |
| 建設處 | 0.72 | 穩定 |
| 農業處 | 0.71 | 稍弱 |
| 國際發展及計畫處 | 0.65 | 稍弱 |
| 臺東市公所 | 0.55 | 偏弱（recall 42%）|
| **整體 val_acc** | **0.76** | |

臺東市公所偏弱原因：訓練資料僅 1,596 筆（警察局的 22%），且業務語意與其他局處重疊。精準度優化非本期重點。

### 5.3 重新訓練時機

- 某局處業務範圍調整（新設局處、業務移轉）
- `/predict` 信心值普遍下降（資料漂移）
- 累積新標注資料達 1,000 筆以上
