# 新專案導入指引

> **版本**：v1.0（2026-05-17）
> **適用對象**：將智慧分案系統導入新縣市或新業務情境的實施人員

---

本系統的模型標籤（局處）與訓練語料均屬特定客戶。導入新專案時，需重新設計標籤、準備資料、建立 config.yaml，再執行訓練。API 介面不需修改。

---

## 1. 確認輸出標籤（分類目標）

| 問題 | 說明 |
|------|------|
| 分派對象是哪些單位？ | 列出完整局處清單，例如：建設局、環保局、衛生局 |
| 有沒有「其他」類別？ | 是否有無法分類的案件需獨立一類 |
| 業務邊界清不清楚？ | 若兩單位業務高度重疊（如環保局 vs 衛生局），模型容易混淆 |

**產出物：`data/labels.txt`**

每行一個標籤，順序即為模型內部 id（從 0 開始）。標籤確定後不應隨意調整順序，否則需重新訓練。

```
建設局
環境保護局
衛生局
教育局
社會局
警察局
```

---

## 2. 準備訓練資料

**格式：純文字 TSV，每行一筆**

```
{標籤}\t{陳情文字}
```

```
建設局	路燈故障已多次通報仍未修復，影響夜間行車安全
環境保護局	工廠排放廢氣，氣味刺鼻，嚴重影響附近居民生活
警察局	檢舉路口違規停車，長期佔用行人穿越道
```

| 項目 | 規範 |
|------|------|
| 編碼 | UTF-8（無 BOM） |
| 分隔符 | Tab（`\t`），不是逗號 |
| 標籤名稱 | 需與 `labels.txt` 完全一致 |
| 資料切分 | train 80% / val 10% / test 10% |

**各類別資料量建議：**

| 類別數量 | 每類最低建議筆數 |
|---------|--------------|
| 5 類以下 | 300 筆 |
| 5–10 類 | 500–1,000 筆 |
| 10 類以上 | 1,000 筆以上 |

---

## 3. 資料清理建議

| 問題類型 | 處理方式 |
|---------|---------|
| 標籤不一致（「建設處」vs「建設局」） | 統一標準化，建立對照表 |
| 文字過短（2~3 字） | 過濾空白與純數字；極短文字可保留 |
| 重複案件 | 完全相同的字串建議去重 |
| 類別嚴重不均 | 各類別差距建議不超過 10 倍 |
| 標籤模糊案件（跨局處業務） | 優先清除，這類資料會讓模型混淆 |

---

## 4. 設計輸入策略

smart-ai `data` 欄位支援多個 key/value，欄位名稱由 `config.yaml` 的 `input_fields` 定義。常見策略：

| 策略 | config.yaml | 適用情境 |
|------|------------|---------|
| 僅標題 | `input_fields: [subject]` | 標題語意清楚、內文雜訊多 |
| 標題 + 內文 | `input_fields: [subject, content]` | 內文有補充資訊 |
| 自訂欄位 | `input_fields: [title, category]` | 有結構化欄位可輔助 |

BERT 最大輸入為 512 tokens（約 400–500 個中文字），超過自動截斷前段。`input_fields` 多個欄位的值會串接後送入模型。

---

## 5. 建立 config.yaml

在 `systems/<system>/` 建立 system 設定（或 `orgs/<org>/` 建立 org 設定），參考既有範例：

```yaml
# systems/<new_system>/config.yaml
org: new_system
org_name: 某縣市政府
num_classes: 8
input_fields: [subject]
pretrained_model: hfl/chinese-roberta-wwm-ext
max_length: 512
epochs: 5
batch_size: 16
learning_rate: 2.0e-5
train_file: data/train.txt
val_file: data/val.txt
test_file: data/test.txt
labels_path: data/labels.txt
model_dir: checkpoints/bert
db:
  field_map:
    label: dept_name
    text: case_title
```

## 6. 完整導入流程

```
1. 確認輸出標籤 → 建立 data/labels.txt

2. 準備訓練資料
   ├── 從業務系統匯出 → 清理 → 轉為 TSV 格式
   └── 切分 train/val/test（8:1:1）

3. 設計輸入策略 → 決定 input_fields

4. 建立 config.yaml

5. 訓練模型（擇一）
   ├── 方法 A（API）：POST /api/v1/train，傳入 DB 連線參數
   └── 方法 B（手動）：執行 GPU 訓練，詳見 GPU訓練操作手冊_BERT.md

6. 驗收
   ├── GET /health 確認服務正常
   ├── POST /api/v1/predict 測試數筆
   ├── 測試集 Macro F1 > 0.70（建議門檻）
   └── 各類別 recall > 0.50
```

---

## 7. 評估門檻建議

| 指標 | 建議門檻 | 說明 |
|------|---------|------|
| 整體 Macro F1 | > 0.70 | 主要評估指標 |
| 各類別 recall | > 0.50 | 避免某類幾乎不被預測到 |
| 整體 val_acc | 參考用 | 類別不均時可能偏高，以 F1 為準 |
